# 名词表

> 所有文档、代码注释、日志必须使用这里的定义。
> 发现同一个词在不同地方指不同东西 → 先改本文，再改别处。

## 一、实体层次

```
节点 (node)  ──绑定──▶  线路 (line)  ──属于──▶  块 (block)
   │                        │                      │
机场的一台服务器         一条 WARP 连接          一个 CF 机房
```

| 名词 | 英文/代码名 | 定义 | 不要混用 |
|---|---|---|---|
| **节点** | `node` / `tag` / 「落地节点」 | 机场（代理服务商）的一台服务器。WARP 流量从这里借道出去 | 不要用来指「出口 IP」，也不要指「线路」 |
| **线路 / 隧道** | `line` / `WARP-WG-7` / `WARP-CF-D` | 一条独立的 WARP 连接。有独立设备身份，因此有独立出口 IP | 「隧道」= 「线路」，同义 |
| **渠道** | `channel` / `WARP-BLK-NRT-REG-0` | 块模型里的分配单元 = (类型, 块, 序号)。**不是**一条实际在跑的线，是"该开一条线"的声明 | 不要和「线路」混用 |
| **块** | `block` / colo | 一个 Cloudflare 落地机房（NRT/PHX/SJC…）。块按 colo 切 | 不要用机场的订阅桶标签（CFB/OLD）代替 colo |
| **成员** | `member` / `WARP-CF-*` | `config.py` 里 `warp.members[]` 的一个条目，是 daemon 眼里的"一条可切换的出口" | 成员 ≠ 渠道；成员是运行期概念，渠道是布线期概念 |
| **出口** | `egress` / `ip` | WARP 分配的公网 IP，opencode 看到的就是它 | 不要用「出口」指代线路 |

## 二、承载方式

| 名词 | 代码名 | 协议 | 经过什么 |
|---|---|---|---|
| **直连 WARP** | `usque-*` | MASQUE over QUIC/TCP（usque 客户端） | 本机直接到 Cloudflare |
| **H2** | `usque-h2-*` | MASQUE over HTTP/2 | TCP 经机场节点中转 |
| **WG** | `warp-wg-*` | WireGuard over UDP | UDP:2408 经机场节点中转 |
| **proxy 池** | `proxy` | 各种机场协议 | 直接是机场节点本身 |

> 「直连」这里指的是**不经过机场节点**，不是「没有代理」。全部四类都是走代理出公网的。

## 三、状态与判定

| 名词 | 字段 | 准确定义 | 最容易误用的地方 |
|---|---|---|---|
| **出口地址** | `ip` | 这条线拿到的 WARP 出口 IP。有值 = 隧道真建起来了 | 只表示"建起来了"，不表示"能用" |
| **成功时间** | `last_ok_ts` | 这条线的出口 IP **在模型层成功服务过**的时刻 | **不是**"隧道通"。`blocked`/`quota` 时会清零 |
| **判定** | `verdict` | 模型层对**这个出口地址**的结论：`OK`/`quota`/`flagged`/`unreachable`/`err` | 描述的是地址，不是线路 |
| **封禁** | `blocked` | 出口被 opencode 判定 403（abusive traffic）或 429（配额耗尽） | 403 和 429 的处置相同，但成因不同 |
| **烧穿** | `burned` / `ban` | 整个 colo 的地址段在窗口内 100% 被封，重启换地址无效 | 不等于"这节点坏了" |
| **新鲜度** | `fresh` | 出口 IP 是否在 24h 复用窗口外、且未被标记 | 「新鲜」不保证「能用」 |
| **生命周期截止** | `expires_at` | 台账条目**最早可以被删除**的时刻。只由生命周期事件推进：真实成功流量打点 / 新一轮惩罚开启 / 精确封禁延长；**被访问、被选中、探测记账一律不续命** | 不是「解禁时刻」（那是 `ban_until`），也不是「最近被碰过」（那是 `ts`）。`ledger_cleanup_mode="expires_at"` 时它是清理唯一判据；且恒 ≥ 该轮最晚解禁时刻（提前删会把封禁中的地址当新地址放回） |

## 四、动作

| 名词 | 函数 | 做什么 | 断流吗 |
|---|---|---|---|
| **换线** | `reconnect_warp` | 把当前出口从一条线切到另一条**已经健康**的线 | 不中断在途 |
| **重启** | `_warp_line_restart` | 重启一条线的进程，换取新的出口地址 | **会掐断在途连接** |
| **换节点** | `_rehome_one` | 把一条线重新绑到另一个机场节点（WG 写配置、H2 切 selector，均不含重启） | WG 单做不断流但**不重启无效**；H2 立即生效 |
| **rebind** | `warp_wg.rebind` | 换节点后重新生成线路配置 | 否（只是写文件） |
| **补刷** | `_refresh_idle_warp` | 把被换下的闲置线重启，换成新鲜出口 | 该线不在服务中 |
| **预热** | `prewarm` | 提前把低质备线全部排进补刷队列 | 否 |
| **主动轮换** | `proactive` | 按配额（或固定时间）主动换线，不等报错 | 不中断 |
| **换线（错误触发）** | `maybe_reconnect_warp` | 403/429 达阈值后换线 | 不中断 |
| **重定位** | `rehome` / `_rehome_held_lines` | 渠道锁命中后，把线临时挪到封禁率更低的 colo | 需重启才生效 |

## 五、四把锁

| 锁 | 字段 | 防什么 | 什么时候必须让路 |
|---|---|---|---|
| **夜间锁** | `night_window` | 夜间重启刷不出新鲜地址（池子干了） | 换了节点之后（池子变了） |
| **渠道锁** | `ban_hold_until` | 整条渠道窗口内 100% 封禁，重启无效 | 换了节点之后 |
| ~~**额度隔离**~~ | ~~`quota_until`~~ | 2026-11-05 已删除（冷却让线在最脏的时候退出战场） | — |
| **小时配额** | `restart_hist` | 同一条线无限重启 | 换了节点之后 |

> 共同点：四把锁防的都是「**在同一个烂地址池里反复抽签**」。换了节点，这个前提就不成立了。

## 六、时间

| 名词 | 含义 |
|---|---|
| **早八点 / reset_hour** | opencode 免费层配额的重置时刻（本地时间 08:00）。也是 IP 池回血的时刻 |
| **夜间窗口** | 默认 20:00 → 08:00。期间重启刷不出新地址 |
| **24h 复用窗口** | `ip_reuse_guard_sec = 86400`。这个窗口内用过的 IP 不优先选 |
| **探测 TTL** | 同一条线的探测结论多久内复用（按 verdict 分档：**OK 1800s** / 瞬时 120s / 持久 600s） |

## 六之二、地址段

| 名词 | 写法 | 是什么 | 不要混用 |
|---|---|---|---|
| **/32 批次** | `2a09:bac1` / `2a09:bac5` | Cloudflare 的父段，全场只有这两批 | 不是「池子」，只是批次 |
| **/48 池子** | `2a09:bac5:55f8` | 一个 colo 的段集合的最小可辨单位 | 一个 /48 不等于一个机房（`bac1:7680~76e0` 由 PHX/SJC 共用） |
| **/64 抽签结果** | `2a09:bac5:55f8:18be` | 一次 WARP 会话拿到的段；重连即换 | **不可选**，不是「一条渠道分到一段」 |
| **/128 地址** | `…:18be::2e5:5e` | 真正被 opencode 计费的单个地址 | 配额按它算，不按 /64 或 /48 |
| **池** | `池 48/64/128` | 某个指纹 colo 底下三级各自**去重**的个数 | 不是「还剩多少干净段」——那是 colo ban 列 |
| **段指纹** | `colo_of()` | 由出口 /64 的第三四段反推的**落地机房** | 与渠道声明的 colo（代理节点所在机房）是两件事 |

## 六之三、配置六面（对账模型）

配置事实分布在六个「面」上，跨源自检（`_config_consistency_check_impl`）逐面对账：

| 面 | 载体 | 谁来对账 |
|---|---|---|
| 声明面 | members（配置声明） | 自检分类一~六（磁盘五面互查） |
| 产物面 | 渲染出的 singbox.json | 同上 |
| 单元面 | systemd 单元 | 同上 |
| 台账面 | line_state | 同上 |
| 档位面 | tiers.json | 同上 |
| **生效面** | 进程内真正加载的 selector 成员（Clash API `all`） | 自检分类七 `selector_drift`；判据唯一来源 `asip/config_projection.py`；`asip audit --runtime-drift` 可手动查 |

**最容易误用的地方**：前五面全在磁盘上——**写盘成功 + 自检通过 ≠ 配置已生效**（INC-017：热重载返回 204 时旧进程仍拿着旧成员）。第六面只能问运行时；API 读不到时结论是「无法判定」，绝不算「一致」。

## 六之四、台账生命周期与影子观测

| 名词 | 代码名 | 定义 | 最容易误用的地方 |
|---|---|---|---|
| **影子** | `ledger_shadow` / `_LEDGER_SHADOW` | P0 旁路试算：用新清理判据对台账算一遍、对比旧判据，不影响生产行为。只回答「切 P2 是否安全」 | 不是监控告警；也不替代测试，只验判据一致性 |
| **干跑 / would-delete** | `_ledger_shadow_sweep` | 用真清理谓词（`cleanup_verdict`）只算不删，产出「若此刻切 P2 会删谁」（`would_delete` / `would_delete_samples`） | 与实删共用同一谓词——两边天然同步，别再造第二份 |
| **起点戳** | `started_at` | 影子观察窗口的起算时刻，落盘 `.ledger_shadow.json`；文件完好时跨重启保留，硬崩溃丢快照则回退重计 | 不落盘的计数每次重启归零，「连续 ≥24h」永远无法证明（INC-019 同款）；门槛必须实查「`started_at` 已是 24h 前」 |
| **分人群** | `shadow_bucket` | 偏差统计分干净档 / 惩罚期档：干净档不计 deviation，`exact_match` 只统计惩罚期条 | 混在一起统计，干净条目的时间戳会被计成偏差（1.79e9 秒假象） |
| **missing_expires** | 影子计数字段 | **可补齐**的缺 `expires_at` 条目数 = 写入口收敛是否彻底的证据（P2 门槛一） | 不是坏数据计数——锚点全坏、补不出的计 `unmigrated` |
| **unmigrated** | 影子计数字段 | 时间锚点全坏、补不出 `expires_at` 的条目数；清理跳过并告警，**永不静默删** | 与 `missing_expires` 混用会污染门槛一的诊断 |
| **单一事实源** | `asip/ledger_policy.py` | 释放时刻 / 判定 / 续命计算的唯一出处：判定、清理、影子、报表全部委托它 | 「各自本地重算」是历史缺陷根因——判据一改，口径必然分家 |

## 七、日志常见词

| 日志原文 | 含义 |
|---|---|
| `块模型接管分配：N 条渠道 → M 条线路` | 块模型生效，共产出 N 个渠道，其中 M 个成了实际线路 |
| `同块换到 <node>` | 轮回守护把一个死节点换掉了 |
| `节点 TCP 通但拿不到出口地址` | 该节点不转发 UDP:2408，跑不了 WARP |
| `渠道锁定中（至 MM-DD HH:MM）` | 命中渠道锁，在此期间不重启（换节点不受此限） |
| `额度隔离中（剩 Nmin）` | 该出口地址的额度未恢复，暂停重启 |
| `TTL 内已有 OK（跳过实测）` | 探测结论缓存命中，省掉一次配额消耗 |
| `等待超时仍无新鲜备线，本次不切` | **没有** `last_ok_ts` 在 120s 内的线。深夜池子干涸时这是常态，不是换线坏了（既定事实第 24 条） |
| `连续 N 次取不到出口地址` | 该线真的拿不到出口 IP（`unknown`）。若是 `quota` 则**不算**（既定事实第 25 条） |
| `模型层: quota（Retry-After Xh）` | 该**地址**的配额耗尽，到点前换出口无意义。隧道本身是好的 |
| `本会话重启 N 次` | daemon 本次启动以来这条线被重启的次数，不是历史累计 |

## 八、容易混淆的三组

### ① 节点 vs 出口
- **节点**是机场的服务器（借道的）
- **出口**是 Cloudflare 给你的 IP（露脸的）
- 换节点不一定换出口（v4 同 colo 就换不到），换出口也不一定换节点（v6 重启即可）

### ② 线路 vs 渠道
- **线路**是实际存在的、有进程在跑的隧道
- **渠道**是布线时的分配声明，可能因为去重、截断而没有变成线路

### ③ 换线 vs 换节点
- **换线**：当前出口从 A 线切到 B 线。B 线本来就是健康的
- **换节点**：把 A 线自己绑的机场节点换掉。换完必须重启 A 线才生效

### ④ 渠道轮换 vs 渠道块内部的轮换 vs 代理池轮换

- **渠道轮换**：渠道之间的切换——WARP 换线/重连、秒切换槽、9router 重试指向新渠道。轮换主体是「渠道」，回答「走哪条渠道」。主动节奏在此层：`_maybe_proactively_rotate_warp`（fixed 时长 / requests 配额格数两种判据）。
- **渠道块内部的轮换**：渠道内部对 IP 的连通性择优——延迟表、延迟分数、预检、判死/冷却排除。被动选择器，内部只有延迟相关逻辑，**无主动节奏**。
- **代理池轮换**：第七闸口（slot-7）对机场池节点的轮换，与「第七闸口轮换」是同一事物。发起权全部在闸口：`/rotate` 报错换（800ms 合并窗）、keeper 死节点换、在役（`proxy_gate_serving_window_sec` 300s）主动换（`proactive_rotate_sec`）。执行：PUT slot-7 自己进程的 `proxy` selector + `now` 回读验证。
- 代理池轮换选节点时调用渠道块内部的延迟择优逻辑（`pick_next_node` → `_filter_candidates`/`_p2c_select`）：借用关系，不是归属。
- 主进程侧的 `_rotate_pool_proactive`/`_rotate_on_error` 只翻主进程 `proxy` selector（落池态，`_pool_should_rotate` 三态判据），翻不到 slot-7 进程。
