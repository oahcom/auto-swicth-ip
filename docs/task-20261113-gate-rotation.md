# 第七闸口（代理池轮换）任务书

- 配套文档：`docs/plan-20261113-gate-rotation.md`（问题与根因，先读这份）
- 状态：**待对齐冻结**。对齐确认前不派活、不改代码。
- 总原则：先结构与可观测（不改行为）→ 再正确性 → 再策略输入 → 最后才是判据语义。任何一步都必须能被上一步建立的指标验证。

## 0. 全局红线（违反即打回，不接受"顺手改"）

1. 不改渠道层：WARP 换线/重连、秒切槽、槽位修整、渠道探测。
2. 不引入任何轮换频率限制：不退避、不节流、不加最小间隔。
3. 不改 P2C 打分器的最优性设计，只改它的输入（身份、计数、判死）。
4. 不改「恢复即回」的优先级与判据。
5. 不为"看起来整洁"做重构；每一处改动必须对应计划书里的一个根因。
6. 结构搬移与行为改动**不得混在同一批**：搬移必须是行为等价的可验证搬移。
7. 不与并行会话的在途改动混提交；提交策略由用户决定。
8. 每个单元独立开关，默认关闭新行为；无量化改善即回滚。

## 1. 为什么按这个顺序切（不是按好修排序）

- 先做 A 组：没有模块边界，B/C/D 的改动都会落在"主路径与闸口共用"的资产上，无法只改一侧；没有台账与字段，任何改动都无法被证伪（上一轮退避的错误正是因此产生）。
- 再做 B 组：并发写与时间证据缺失是**纯粹的正确性缺陷**，不依赖新指标，也不会改变策略偏好，风险最低、收益确定（消除 423 条白报障与 4 次假失败）。
- 然后 C 组：把"成功"从配置态切到业务态。这一步依赖 A2 的台账，否则没有数据来源。
- 最后 D 组：候选集与记忆的修正会改变选择分布，必须在能测命中率之后再做，否则无法判断好坏。
- E 组贯穿：每一组落地后都要跑同一套观测，形成前后对照。

## 2. A 组：结构与可见性（不改变任何行为）

### A1 模块骨架 `asip/gate/`
- 依据：计划书 R3/R4/R5/R6 均落在共享资产；无边界则无法安全分治。
- 交付：`asip/gate/` 包（policy / state / actions / health / config / tests）+ 单一 Facade；`daemon.py` 只保留构造、依赖注入、两条调用（UDS /rotate、keeper）。
- 切法：**纯搬移**。搬移前后用现有全量测试证明行为等价；任何语义变化都拆到 B/C/D 组。
- 验收：模块不 import daemon、不 import config；测试可在无 daemon 全局状态下运行；`daemon.py` 中不再持有池状态。
- 红线：不得在搬移批次里"顺便"改判据或参数。

### A2 轮换结果台账
- 依据：R2（无反馈闭环）。
- 交付：每次轮换记录（旧节点、新节点、原因、时刻、出口族若可知）；下一次同签名报错到达时回填「上次轮换存活秒数」；只读导出（debug 端点 + 日志字段）。
- 关键设计：必须持久化，重启不丢（否则每次重启清零，等于没有）。写入路径不得阻塞 /rotate 关键路径。
- 验收：能直接算出命中率，且与日志抽样对齐；重启后台账仍在。

### A3 可观测补齐
- 依据：R7。
- 交付：`_api_stats` 纳入池闸轮换；`/slots` 如实反映闸口在役与出口；日志补出口协议族、上一节点在役时长、轮换后首个结果。
- 验收：stats 的池闸计数与实际轮换数一致；`serving` 不再恒 false。

## 3. B 组：状态一致性（纯正确性，不改策略）

### B1 selector 写入串行化
- 依据：R6 现象一。keeper 换节点不持锁，与 /rotate 可同秒对同一 selector 各写一次。
- 交付：两条路径走同一串行入口；任何 selector 写入都可追溯到调用方（日志带来源标识）。
- 验收：连续观测 6h，PUT 后回读不符 = 0；同秒双写 = 0。

### B2 池闸自己的 `switched_at`
- 依据：R6 现象二。该字段唯一写入口只服务 WARP 槽。
- 交付：池闸真实换节点时写入自己的换线时刻；回执不再引用一个恒为 0 的字段。
- 验收：合并窗内被吞掉的请求，回执可重放率 ≥95%（现状 0%）。

### B3 合并窗回执语义
- 依据：R6 现象三。池闸「合并即全丢」，与主路径「合并不换线、证据照收」不一致。
- 交付：合并窗内的请求要么拿到刚发生的那次换线的时间证据与目标节点，要么明确回「已合并」，不得回「无可用闸口」。
- 验收：「无可用闸口」回执中，属于合并窗的比例从当前高位降到接近 0。

### B4 预检移出锁
- 依据：M6 的影响面。锁内已含最多 3×10s 预检，扩锁会加剧延迟。
- 交付：锁内只做「读状态—决策—写 selector」，预检在锁外完成，结果作为决策输入。
- 验收：/rotate 在锁内耗时下降；B1 落地后不再出现"扩锁导致延迟上升"。
- 依赖：与 B1 同批，不可拆开上线。

## 4. C 组：判据语义（依赖 A2）

### C1 健康两维化
- 依据：R1。ok 有三个来源、语义混杂。
- 交付：连通态（既有 gstatic 探针）与业务态（来自 A2 台账）分开报告；不再合并为单一 ok。
- 验收：能回答「当前 ok 的节点，上一次业务结果是什么」。

### C2 「成功」切换到业务态
- 依据：R1。
- 交付：轮换成功 = 观察窗内无同签名报错；PUT 成功只表示「已写入」，不再等价于成功。
- 验收：建立「ok 但下一次即失败」基线，并逐版下降。
- 红线：不得因此改变轮换触发条件。

## 5. D 组：候选集与记忆（依赖 A2 + C2 的指标）

### D1 停止污染写入
- 依据：R4。
- 交付：不再从主进程 7890 向池节点写出口 IP；已有脏值标记不可信，退出一切判断。
- 验收：新写入不再出现"多节点共享同一值"；去重输入为空时有明确分支（不得回退成"全部同组"）。

### D2 去重停用或分层
- 依据：R4（203→62）。
- 交付：先量化主路径对去重的依赖，再决定全局停用或按数据来源分层。
- 验收：有效候选数从 ≈62 回到 ≥180（扣真实死节点）；被选中节点分布覆盖到此前零命中的 48 个节点。

### D3 累计惩罚冷却（分层视图）
- 依据：R3。60s 固定冷却 vs 小时级故障。
- 交付：同一节点被换下次数累计，冷却随次数递增；闸口维护自己的惩罚视图，不写主路径共享冷却表语义。
- 验收：同节点重复被选次数分布右移；命中率同步上升。
- 红线：不得变成"频率限制"——允许持续尝试其他节点，只把已被证明烧过的节点排到队尾。

### D4 判死门槛与重启宽限
- 依据：R5。
- 交付：单次失败不进死表；要求跨探测轮连续 N 次；重启后首轮不判死；死表跨重启保留或在宽限期内不写。
- 验收：单次失败判死占比从 91.8% 降到 <10%；重启后成批判死事件从 12/16 降到接近 0。

## 6. E 组：验证与上线

### E1 测试
- 每个单元带模块内测试；A1 搬移用现有全量测试证明等价；B 组需要并发用例（两条写路径同秒）。
- 验收：全量 pytest 绿；新增用例覆盖计划书每条根因。

### E2 生产观测
- 指标：命中率、有效候选数、单次失败判死占比、PUT 后验证失败、回执可重放率、stats 一致性。
- 方式：每单元上线后观察同口径前后对照，不得用不同窗口比较。

### E3 启用与回滚
- 逐单元启用，默认关闭；任一指标无改善或恶化即回滚该单元。
- 回滚演练必须在上线前完成一次。

## 7. 并行度与依赖

- A1 与 A2/A3 可并行（不同文件区域），但 A1 涉及搬移，必须先合并 A1 再让 A2/A3 落在最终位置上。
- B1+B4 必须同批；B2、B3 可在其后并行。
