# 04:58:20 报错定位 + 高延迟归因报告

## 一、报错根因（req=wfgkef17a，Total 37595ms / TTFT 0ms）

时间线（9router + daemon 日志交叉）：

| 时刻 | 事件 |
|---|---|
| 04:57:43 | POST（2 MSG 小请求），HEADROOM 压缩等满 3s 超时后 fail-open |
| 04:57:46 | 经 7890 发出，**1 秒内吃到 429**（FreeUsageLimitError） |
| 04:57:47 | 记账换线 → daemon 回 `already_retired` **不换线**（判据：报障 IP 台账里"曾被换走"）→ 重试 1/2 |
| 04:57:47→04:58:08 | 重试打在**同一个死 IP** 上 → header-timeout **20.7s**（transport stall） |
| 04:58:08 | 再报 → daemon 又回 `already_retired` 不换线——**daemon 自己日志实锤矛盾**：<br>`请求地址 2a09:…:3a3:55 在请求发出后被换走（当前 WARP-H2-FRA-77 / 2a09:…:3a3:55）`<br>**请求地址 == 当前出口**，"已换走"是假的 |
| 04:58:08→04:58:20 | 45s 预算的重放又打在同一个死 IP → 429 |
| 04:58:20 | 记账 ok 换到 slot-6，但"no second replay"预算耗尽 → ERROR 429 37.6s |
| 04:58:20 | combo model 2/10 回退 **1 秒后救回**（但前 37.6s 全是浪费） |

**根因：`already_retired` 的两条判据都会说谎**
1. exit ledger 只看"这个地址**曾经**被换走"——IP 回收后同一个 /128 又回来，旧记录还在，于是恒判"已换走"；
2. `switched_at > request_started_at` 是时刻推断——重试发出晚于换线，但传进来的还是**原请求**的开始时间，恒真。

两者共同后果：判"原地重连即可"，但重连的还是同一个死 IP → 20s 超时 → 再判 → 再撞，白烧 30s+。

## 二、修复（已部署）

**daemon.py（05:25 重启生效）**
- `_rotate_slot_once` / `_rotate_once` 各加**事实 veto**：报障地址 == 当前出口 → 否定"已换走"，走真换线（标脏 + 备槽跳板）。
- veto 只用于否定"已换走"，不用于肯定（沿用原设计原则）；判不出时行为不变。

**9router opencode.js（05:28 构建部署，check_deploy_state = MATCH `Edq9PK5iI`）**
- 三发循环每发把 `attemptStartedAt/attemptEgress` 写回 holder——stall 重放记账不再带原请求时刻（消除时刻推断说谎的源头）；
- `lineMoved` 加客户端 veto：`already_retired` 但回包 `active_egress` == 本发失败地址 → 不算"线已换走"，拒绝原地白打（fail fast 交给 combo 回退）。

**测试**：daemon 新增 `tests/test_already_retired_veto.py` 4 例（veto 命中/迟到报障不动/时刻推断照旧/仅时刻推断也否决）+ 相关套件 56 全绿；9router asip/429 簇 **106/106 绿**。

预期效果：同类链条从"3 发死 IP × 20s = 37-113s 后失败"收敛为"1 发 → veto → 真换线 → 重试上健康闸"。

### 可无损减掉的延迟（按收益排）

1. **死 IP stall 链（A+B ≈ 410 条 >20s + 部分 >40s 长尾）**：本次修复。极端例子从 100s+ 收敛到 ~20s 内重试上健康闸。
2. **HEADROOM 3s 税**：服务挂了（203/EXEC，二进制丢失）但客户端每请求**白等满 3s 超时**才 fail-open——实测 **1109 次 × 3s ≈ 55 分钟纯等待**。你在修服务；建议顺手在 headroom.js 加连续失败熔断（3 次失败后 60s 内直接跳过不等待），防再次静默挂掉。（我派的子代理已撤回，没碰 headroom 任何文件。）
3. **C 类里约 3s 是 headroom 税**：TTFT 是从请求开始算的，恢复压缩还能减 IN 体积（100K→更小）→ 上游 TTFT 成比例下降。

- TTFT p50=10.6s：free 档 + 10–25 万输入 token + THINK:high 的推理排队，换线/换闸救不了；
