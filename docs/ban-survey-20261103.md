## 异常点

1. **5 条 H2 通道整窗零成功出口**：NRT-0、NRT-1、TPE-5、ICN-10、SLC-11（+SLC-12），
   合计约 900 次重启、产出 0。它们把 H2 重启成功率从 ~95% 拉到 77.8%，并占掉大半空转计数。
   这批不是"被封"，是**根本没拿到过出口**，所以 ban 率为 0 不代表干净。
2. **H2 tag 的 colo 不可信**：H2-LAX-2 实测 100% 落 **OLD/PHX**，H2-ORD-9 有 40% 落 PHX。
   `channels.json` 里的是渲染时预期值。任何按块模型算的 ban 率都必须用实测落点。
3. **CF 系是唯一还活着的一类**，但量小（416 记录 / 188 唯一 IP），且 CF 桶的 /64 只有 8 个、7 个已封。
4. 台账当前未封的 214 个 IP 里，HKG 62 / SIN 61 占了大头——但它们下一秒就可能被烧，别当储备看。

## 口径（与旧文档容易对不上的地方）

- `.warp_ip_history.jsonl` **一行 = 一次 `_mark_warp_ip_used` 调用**，不是一次请求。
  ban 率 = 被标封禁的使用记录 / 总使用记录。
- 台账 `served_sec`（中位 ~20h）是 `now - first_seen`，**不是存活时长**，
  与"寿命 8s"不矛盾：first_seen 是地址首次入账，中间的 idle 时间也算进去了。
- 9router `requestDetails` **只保留最近 1000 行**，做不了整窗统计，只能当抽样。
- 同一 IP 在窗口内被多条线报过（1,079 个），按时间就近分配，极端并发下会把失败算到相邻线。
