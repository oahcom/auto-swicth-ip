## 0. 名词

| 词 | 意思 |
|---|---|
| 槽位（slot） | 一个独立的 sing-box 进程。全系统 7 个，slot-1..slot-7 |
| 第七闸口 / 池闸（slot-7） | 兜底槽位，端口 7897、Clash API 9097，选择器名 `proxy`，成员是机场池节点 |
| 选择器（selector） | sing-box 里的「虚拟出站」：内含节点列表 + 一个当前选中项。7 个进程的选择器**同名**（`opencode-out` / 池闸 `proxy`），不带进程标识 |
| 入口名（tag） | 节点在选择器里的名字，形如 `cn.bing.com:443~7-any`。`~N` 是同 host:port 撞名时的**到达位次**（从 2 起，无 `~1`），订阅换序即漂移 |
| 出站（outbound） | tag 层概念：选择器里的一个成员名。「出站 ≠ 出口」——一个出站可换出口，一个出口可挂多个出站 |
| 出口（egress） | 真实落地的服务器地址（IP）。**出口级额度消耗在它身上** |
| 主体（subject） | 记账的挂靠单位。**本项目定为出口级**（见 §1），主体 = 出口 IP；凭据摘要只做身份识别与账号级告警维度 |
| 配置指纹 | 纯函数，parse 时可算：`server｜port｜type｜transport｜path｜host｜SNI｜凭据摘要`。与网络无关 |
| 物理出口身份 | 运行时值：`实测出口 IP + 凭据摘要`。必须实测，禁用任何静态推断 |
| 凭据摘要 | 凭据字段按协议取：vless/vmess → uuid；anytls/trojan/ss → password。取不到 → 标 `credential_unknown`，不进账不参与去重 |
| 别名（alias） | 同一出口（同一主体）下多个 tag 的互称。组内不是竞争者，是别名 |
| grouping_level | 去重/分组的层级声明：`entry`（按 server,port）/ `egress`（按实测出口）/ `subject`（按出口+凭据）。必须显式声明，禁止静默冒充 |
| 选中次数 vs 请求数 | 前者=被 pick_next_node 选中的次数；后者=承载的真实 HTTP 请求条数。**额度单位是请求**。二者不可混记 |
| 回滞口 | 策略模式切换的回滞判据。现网「pressure→normal：错误率达标**或样本总数<3**」——驻留时长由采样窗口决定 |
| 原语闸 | 测试/迁移期在 selector 写入原语（PUT 点）上装的总闸，暂停时拒绝写入并记日志 |
| Retry-After | 上游在 429 里给的「多少秒后再来」。实测 **46799** 秒（≈13h，node_cap3_scan.json）|
| 出口级额度 | 换 IP 能绕过的额度（主账本记这层） |
| 账号级额度 | 换 IP 也绕不过的额度（只做告警维度，不进主账） |
| 判死 | 把节点从候选里剔除一段时间 |
| 观测 / 盲切 | 调度器看得见 / 看不见 9router 的请求，决定走哪条选点策略 |
| 有列、无写入 | 表里有这一列，但没有任何代码路径给它写过非默认值 |

## 1. 资源模型与账本单位（B2 已拍板）

| | WARP | 机场 |
|---|---|---|
| 出口 IP | 会被封，可无限换新 | 固定一批，每台基本只有你在用 |
| 每个出口的额度 | 几乎不限 | 实测 **0–358**（外部文档计额口径，opencode-429-limit-model-20261112.md；「集中 130–360」为包络概括非逐字引文；「200–300」是约数）。**口径注意**：该数按 IP 计额，与「主体=出口+凭据」粒度不同级——同 IP 多凭据时主体级聚合额度更高，设计按保守值（IP 级）取 |
| 最优策略 | 发现被烧 → 立刻换新 IP | 谁用过、用了多少、下一个该用谁 |
| 换的动作本身 | 免费 | 要花一个新节点的额度，且那一次请求可能失败 |

同一套调度器在这两种约束下最优策略**相反**。现网代码照 WARP 写、跑机场池——这是全部问题的总源头。

**账本单位 = 出口级**（已拍板）：额度、冷却、ban 全部挂在**出口 IP** 上。凭据摘要只做两件事：① 身份识别（区分同机不同账号）；② 账号级 429 的告警维度。账号级额度不进主账——它在你的场景里是例外（订阅商限速），不是常态。

由此定死下游三个口径：S6「换节点有效」只对出口级成立，账号级 429 走告警不走换节点；S4 打分依据 = 出口的剩余额度；S5 分组键 = 出口。

- **79% 判死单次失败**——实测 93.4%（事件级）/ 51.2%（节点级）。79% 疑从错配率串号。
- **pressure 驻留 9 秒 / 全文 34 行**——取自单份轮转日志的单次事件（34 行≈一份日志的量），全量是 2815 行、33 段、抖动。

## 3. 因果链（按修复依赖排序）

### R1 · 最上游的可观测性缺口（拆 R1a/R1b）

请求由 9router 直打 sing-box mixed 入站，**daemon 全程不代理流量**，只在换线那一刻 PUT 一下选择器。

- **R1a「哪个出口正在服务」**——daemon 视野里不存在（它只看到换线瞬间）。
- **R1b「承接了多少请求」**——daemon 结构上看不到；9router 有请求数但无节点字段，两侧无共同键。

R1 是**修复依赖的最上游**（修它解锁 S3/S4/S6 的判据；S5 的分组键来自 3a/3b 实测，不来自 S1），不是唯一因果起点：`~N` 漂移（R4）来自订阅解析，独立于 R1 存在；R1 只是让账挂错**无法被察觉**（放大器）。反事实：去掉 R1，R4/R5/R6/R7/R8 症状仍在；去掉 R4，R1/R3 仍在。多因一果，R1 排第一的标准是「修复解锁面」。

### R2 · 于是只能用代理指标推断

延迟（越快越被反复选）、9router 错误率（烧穿后才上升）、最近 5 个名字（只挡 5 个）。三个都不等于额度 → 分配必然退化成集中使用少数节点。

### R3 · 「用过」这个量，记了错的东西

不是「空」，是三层错：

1. **`call_count` 列有列、无写入**（171/171 = 0，唯一带参写入点不传参）——列是死的；
2. **内存字典数的是「选中次数」不是「请求数」**（主动轮换 233 次/21.5h 可记），量纲错位；且 **1200 秒双清**（9 次重置/20 次跳过）；
3. **请求侧有量无归属**——usageHistory 47 万行无节点/出口字段，与 daemon 侧无共同键。

所以请求级用量只能靠**估算**（连接级摊分），不能靠「接线」。

### R4 · 身份三种失效方式（全部已在生产发生；机制与量化为单方结论，见 §2.2）

| 失效 | 机制 | 已发生的证据 |
|---|---|---|
| 台账 IP **测量错** | `fetch_node_ip_region` 收 node 不用 node，恒测 7890 | 67 桶伪影（update_ts 聚 14:43–16:33）；日志三连错位 |
| 报表指纹**缺字段** | 键 `(SNI,type,password)` 不含 server；vless 凭据是 uuid 取不到 | 23 个 vless 被误并（同 uuid 跨 23 个 server）；73 个跨 server 合并全无实测 |
| tag **位次漂移** | `~N` = 到达位次，换序即换义；状态表无指纹列 | 结构性必然；同机双 tag 活例 2 对 |

额度挂出口，系统却按名字/tag 管账——记账单位错位是 R4 的总括。

### R5 · 策略抖动，且打分信号不是用量

`_strategy_mode` 默认 normal（延迟优先），pressure（均匀分散）由错误率触发。**实测是抖动不是一边倒**：33 段 pressure 累计 17.4h vs normal 3.39h，历史四份日志 pressure 主导、近两份翻回 normal。机制在回滞口：「pressure→normal：错误率达标**或样本总数<3**」——驻留时长由采样窗口决定，不由策略优劣决定。

关键推论：**90.2% 由 429 触发的轮换，大量发生在 pressure 期间**（推论：两数各有源，联合时序未单独取证）——把 pressure 变默认（v3 S4）是空杠杆。真正的病是：无论哪个模式，打分依据都不是「这个出口还剩多少额度」。

### R6 · 去重：分组键错 + 用量盲粘性

- **R6a 分组键错**：按台账里的错 IP 分组（R4 的直接后果），候选坍缩到约 1/3（快照制：20:15 测 202→62 组/剔 140；21:30 现算 198→66/剔 132——node_info.ip 持续漂，精确数随快照走，**量级稳定在剔除 2/3 左右**）。
- **R6b 排序键恒 0 + 刷新时机**：组内按 `call_count` 升序，该列恒 0 → 并列 → 稳定排序 → **粘性**（只要第一个可用就一直赢）。不是「永久锁定」：可用性一变（判死/冷却/最近窗口）赢家就换（v2 实测大桶内下标最小者被选 3 次、另一个 9 次，见 §2.2）。真正的锁是输家 IP 只在被选中后才刷新——选中机会少 + 数据陈旧的正反馈。

且同组成员若同主体，用量**恒等**，「组内按用量轮换」在数学上不可能（见 S5）。

### R7 · 429 语义错位

被当 60 秒限速，冷却后再打。Retry-After 实测 **46799 秒（≈13h）**，系统只拿它覆盖默认值。60s vs 13h 的机制差决定了「冷却后再打」几乎必然仍在惩罚期。出口级换节点在机场模型下有效（节点≈出口），账号级无效——两层的判别信号缺位（S6 补）。

### R8 · 判死是放大器（量化为单方结论，见 §2.2）

事件级 93.4% 的判死来自单次探测失败；复测存活 91.7%。在「节点基本都可用」前提下绝大多数是误判；候选只剩 62 组，误杀 singleton 组即整组失效。判死键仍是 tag，会随换指嫁错（R4）。

### R9 · 同一写入函数的两个入口无互斥

rotate 路径持 `_API_LOCK` 调 `_proxy_gate_rotate_node`，keeper **不持锁**调同一函数——4 次「PUT 204 但回读不符」全部同秒配对 keeper。修法是互斥/单飞，不是「收敛写者」（PUT 点本来就只有一个）。另有池成员漂移无告警项（磁盘 198 / 运行 202），热重载不重建出站、自愈跳过池闸。

## 3.5 设计约束：能复用的就复用，公共代码放公共模块

**已有能力清单（禁止重写）**

| 已有能力 | 在哪 | 禁止 |
|---|---|---|
| Clash API 客户端（读写选择器/查成员/查连接） | `asip/clash_client.py` | 自己写 HTTP |
| 出口实测（trace URL、IP 探测、地域解析） | `asip/egress.py`（`probe_egress` 需传入已指向目标的端口） | 自己调 ipify/ip-api |
| 原子写 | `asip/atomic_io.py` | 各写各的 json.dump |
| 脱敏 | `asip/redact.py` | 自己过滤敏感字段 |
| 成员比对（WARP 线） | `asip/config_projection.py`（**池成员禁用**，见硬禁令） | 写第二份集合比较 |
| 台账策略（ban_until、rate429/abuse403 分档、解禁时刻） | `asip/ledger_policy.py` | 新建第二套 429 状态存储 |
| 临时探测装置（临时实例、端口分配、孤儿清理、锁） | `dormant_probe`（build_tmp_cfg / probe_one / free_port / kill_orphans） | 另起一个「类似的」测量器（kill_orphans 按进程名前缀杀孤儿，会互杀并把对方节点记成死） |

**硬禁令（写进任务书「禁止」栏）**

1. **禁止复用 `fetch_node_ip_region`**——收 node 不用 node，67 桶伪影的机制来源。
2. **禁止用 `config_projection.compare_members` / `_slot_members_drift` 判池成员漂移**——known_line_tags 只放行 WARP 线，池节点全被过滤，恒判 consistent（198/202 漂移就是被它放过的）。
3. **禁止 `tools/block_view.node_identity` 参与去重/计量**——键缺 server，实测把 197 压成 89（23 个可证误并）；修好前只作报表快照。
4. **禁止另起独立测量实例**——并入 dormant_probe 同一轮次。
5. **禁止把 tag 拉回记账键**——per-name 计数等方案一律不做（R4 的病根）。
6. **禁止退避状态机回填**（阶段 0 已清场的 6 键与实现不得以任何形式回来；允许新增键但不得复用其名与指数退避语义，惩罚状态一律走 ledger ban_until）。

**重复实现收敛**：节点指纹现有两份逐字段相同的复制（parse_subscription / dormant_probe）+ 一套失效的（block_view）。抽到 `asip/identity.py`，**双函数**：`配置指纹()`（纯函数，含凭据摘要）与 `物理出口身份()`（实测出口+凭据摘要）。指纹变更须版本化：旧 fp 按旧值迁移，禁止重算（重算=沉睡池全表失配=判死一次性回池）。

**模块归属**：跨槽位跨用途（选点、去重、身份、计量、额度状态）→ `asip/` 公共模块；只有第七闸口用的编排（池闸 /rotate 语义、池内换节点、恢复即回）→ `asip/gate/`（**包**，不是单文件）。跨槽共享层（槽位状态机、keeper、`_pick_healthy_slot`）**留 daemon 或公共侧**，gate 只收显式传入的状态，禁止 import daemon。

## 4. 方案（每个必须回答：凭什么解决对应的那一环）

### S1 · 给请求补归因（对 R1a，部分对 R1b）

从 sing-box 的 connections 接口读活跃连接的出站链，按出站聚合。**覆盖全部 7 个进程**（各自的 Clash API 9090/9092–9097 的 /connections；7890/7892–7897 是 mixed 入站口，**不是 API 口**——本项目核心 bug 就是误用 7890，这里不许再混；选择器同名，事实表主键必须带 slot 维度：时间×slot×selector×outbound，否则 7 进程同名出站混成一条）。复用 clash_client/atomic_io/redact。

**为何解决 R1a**：唯一不需要 daemon 代理流量就能持续看见「谁在服务」的路径（不与「不改 9router/不代理流量」冲突）。「唯一」不成立（v2ray stats、access log 也是观测面），选它的理由是现成封装 + 连接级事实够 S3 起步。

**边界**：连接级 ≠ 请求级（keep-alive）；R1b 只能估算，留给 S3 校准。验收用注入式金标准（钉 selector 发 N 条短连接，断言事实表出现该 slot/tag，漏归因 ≤5%），时间戳对齐只是辅助（无共同键）。

### S2 · 定义记账主体（对 R4）

主体 = **出口 IP**（账本键，B2 已定）；配置指纹加凭据摘要做身份识别；物理出口身份靠 B10 实测（见任务书阶段 3a）。名字→主体映射落盘，tag 漂移不影响归属。

**为何解决 R4**：三种失效各堵一个——测量错（禁 fetch_node_ip_region + 原语闸实测）、缺字段（凭据按协议取，vless 取 uuid）、位次漂移（账挂出口不挂名字）。**必测用例**：同 uuid 的 10 个入口，若实测出口确不同，必须得到 10 个不同主体（防实测错时 10 节点坍缩成 1 主体、10 份额度记 1 份）。身份层的区分（同机不同账号）由凭据摘要承担，**不进账本键**。

**代价**：出口实测是一次性成本 + 周期刷新；每节点至少 1 次请求额度。

### S3 · 建立计量（对 R3）

把 S1 的「谁在服务」按连接摊分到主体（出口），得到**估算的请求级用量**，标注误差；持久化，废 1200 秒清零（内存字典降级纯缓存）。`call_count` 列处置：先停写 + 观察窗，再删（与并行会话的台账生命周期改动解耦，等其入库稳定）。

**为何解决 R3**：把「有列无写入 + 量纲错 + 无共同键」变成「出口上有估算用量且不被清零」。不做 daemon 代理流量来记账（风险大于收益）；不做 per-name 计数（tag 不得回记账键）。

### S4 · 用账分配（对 R5）——杠杆是回滞口与打分，不是默认值

三件事：① 打分依据从「延迟/选中次数」换成**出口剩余额度**；② 回滞口改造——「样本<3 即回 normal」改为有最小驻留与足够样本量的判据；③ 清零策略处置（与 S3 一致）。

**为何解决 R5**：实测 pressure 已是主态之一（17.4h）且 90.2% 轮换照旧由 429 触发——改默认标签是空杠杆。回滞口决定「驻留由采样窗口决定」这个病，打分决定「挑最快」这个病。两刀都砍才断正反馈。

### S5 · 修去重：分组键换真实出口 + 别名模型（对 R6）

- **R6a**：分组键从「台账错 IP」换成 S2 的实测出口（`grouping_level=egress`；实测覆盖率 <95% 时降级 `entry` 级并**显式声明**，`egress_unknown` 计数响亮）。
- **R6b**：组内**不排序竞争**——同主体的多个 tag 是**别名**，选别名规则：探测新鲜度 TTL（取 dormant_probe 轮次 ×1–2，不硬编码）；**剔除 dead 后**全组 stale 走**持久化轮次游标**（重启不归零，禁止静默回第一条——那是 R6 原病）；全 dead 落「不可用组」不产生候选（验收已单列）；**不按延迟选**（会把「快=好」带回来）。

**为何解决 R6**：候选从 62 组回到实测出口数（分母=实测值，不是名义 202）；粘性由别名规则显式管理。**明确放弃**「组内按用量轮换」——同主体用量恒等，数学上不可能；轮换对额度无益（同出口就是同份额度）。

### S6 · 重定义 429（对 R7）

先判归属，再动作：**出口级**（同出口换账号仍 429 / Retry-After 量级+该出口近期用量指向额度耗尽）→ 硬冷却到 Retry-After 时刻 + 换节点（机场模型下有效）；**账号级**（同凭据跨出口仍 429）→ 该凭据下节点冷却/停用 + 告警，**不判死、不换节点**。状态写 ledger_policy 的 ban_until（扩展，不新建）。

**为何解决 R7**：无效重试从一串变一次；两层额度判别信号补上，防止「账号级被当出口级 → 无脑换节点烧整池」或反向误杀。

### S7 · 判死（对 R8）

前置从「单次探测失败」改「连续 N 次 + 与用量交叉验证」；判死键迁到出口/主体（配合 B9 迁移）。

### S8 · 工程健壮性（对 R9）

同一写入函数的两个入口**互斥/单飞**（同刻最多一个在途）；池成员漂移**自建 known 集**（禁 compare_members）纳入自愈与告警，正向用例=人为删一个池成员必须报 drift。

## 5. 因果对应

| 根因 | 方案 | 修好的判据（定性；量化判据只在任务书） |
|---|---|---|
| R1 看不见流量 | S1 | 每个出站的服务状态可查询（7 进程） |
| R3 记错的量 | S3 | 出口上有估算请求数、随时间递增、不被清零 |
| R4 身份三失效 | S2 | 名字怎么变，主体恒定；同机不同账号**身份**可区分（主体同为该出口，凭据摘要承担区分，不进账本键） |
| R5 抖动+错信号 | S4 | 打分随剩余额度；驻留不由采样窗口决定 |
| R6 错键+粘性 | S5 | 候选回到实测出口数；分组层级显式声明 |
| R7 429 语义 | S6 | Retry-After 内不重打同一出口；归属分层处理 |
| R8 判死误杀 | S7 | 复测为通的不再判死 |
| R9 并发写/漂移 | S8 | 同刻单写在途；漂移必告警 |

**顶层结果指标**（机制判据全过≠病好）：四项指标与「池可服务时长」公式**只在任务书 §3 维护**（此处不复述，防两书漂移）。

## 6. 明确不做

1. **不让 daemon 代理流量来记账**——重写转发路径，风险大于收益。
2. **本批不改 9router**——但不是红线：它是本机自有服务，「加一个上游节点字段」是请求级归因最短路径。不做是因为动别人的服务面（升级/兼容/对方在途改动），列为候选，S3 的估算误差不可接受时重新评估。
3. **不改 `~N` 生成规则**——位次语义波及一切按 tag 存的状态；替代方案是 S2 让新账不依赖 tag + **B9 把旧状态迁出来**（迁移不是改键名，是先清洗再迁移，见任务书）。
4. **不先修判死**——候选坍缩（R6a）不修，修判死只是 62 组里少误杀几个；但容量收益非零（节点级误判 51.2%、singleton 组整组失效），S7 仍排后但不做容量承诺。
5. **不做 per-name 计数 / 不把 tag 拉回记账键**。
6. **不引入新第三方依赖**。

## 7. 总体验收（定性）

全部阶段完成后看四件事：① 出口上的估算用量可信（S2 必测用例 + 注入金标准过）；② 候选 ≈ 实测出口数且分组层级显式；③ 429 后 Retry-After 内不重打同一出口、账号级 429 走告警；④ 顶层结果指标（§5）改善。**量化判据、样本量、阈值、失败归属全部在任务书**，本文件不重复维护。

## 8. 风险与回滚

| 风险 | 触发 | 回滚 |
|---|---|---|
| connections 轮询开销 | 池规模增长 | 降采样；只保留活跃出站 |
| 请求级计数是估算 | keep-alive 下连接≠请求 | 只作 S4 打分依据；误差标注，不进硬考核 |
| 出口实测本身消耗额度 | B10 全量测量 | 并入 dormant_probe 轮次共享成本；可牺牲节点 |
| 长连接不迁移 | 切 selector 不动在途连接 | 分配只作用新连接；验收按新连接统计 |
| 跨槽共享同一出口 | 多槽同时用一个出口（实测有） | 账本按出口聚合不分槽；同出口多槽使用告警 |
| 出口 IP 漂移 | 主体随出口变 | 主体迁移规则（旧账继承/退役）+ 映射 TTL |
| 账号级 429 | 换节点无效 | 归属判别信号 + 告警路径 |
| S4 改回滞口后整体延迟上升 | 分散后慢节点被用 | 单键回退回滞口参数 |
| 凭据摘要碰撞 | 同摘要不同账号 | 摘要加盐；vless 取 uuid、缺失显式报错禁哈希空串 |
| 迁移期候选归零（B9 的迁移条目≈整池，规模见 §2.2） | 一次性翻状态 | 分批 + 容量护栏（低于迁移前 80% 暂停）|

每个方案独立开关，默认旧行为，灰度逐个打开。
