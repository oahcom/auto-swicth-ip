# 换线（switching）

> 本文回答：什么时候换出口？换到哪一条？为什么选线要按 IP 分四档、按 /64 静置、把冷却线垫底？

## 一、换线 vs 换节点 vs 重启

三个动作经常被混为一谈，它们解决的完全不是同一件事：

| 动作 | 做什么 | 断流吗 | 解决什么 |
|---|---|---|---|
| **换线** | 当前出口从 A 线切到 B 线 | **不中断在途** | 当前出口被限流/被封 |
| **重启** | 重启一条线的进程 | **掐断在途** | 这条线的出口地址要换 |
| **换节点** | 把线绑到另一个机场节点 | 单做不断流，但**不重启无效** | 节点跑不了 WARP |

**为什么换线优先**：被换下的那条在后台慢慢刷新，在途请求不断。原地重启有几秒断流。

## 二、什么时候触发换线

| 触发 | 判据 | 冷却 |
|---|---|---|
| **错误触发** | `abuse403 ≥ 1` 或 `rate429 ≥ 1`，且**连错 ≥ 3 条** | 5s（`full_err` 时绕过） |
| **主动轮换** | `requests` 模式：成功 dsv4 调用满 150 格 / `fixed` 模式：每 60s | 同上 |
| **回切（proxy → WARP）** | 池健康连续 3 次全失败 / 池节点 403 达 5 条 / 黑名单占比 ≥ 50% | — |

### 为什么阈值是 1，却还要「连错 ≥ 3」

阈值 1 = 出现任一出口级拦截就**进入换线判定**；但真正的换线要连续 3 条出口级
错误。最近两条报错仍不换，第三条连错才换 —— 对应「刚切线的 10 秒内允许出现
2 次报错而不切线」。

**门控位置很关键**：在**采样/标脏之后**。连错 1~2 条时出口已经收到 403，
仍要标脏 IP、记周期样本，只是暂不换线。

**窗口至少 3 条**：`count_warp_blocked_since` 取 `max(RECENT_WINDOW, 3)`。
配置的 `recent_window=2` 是策略侧口径，2 条窗口下连错数最多数到 2，门控恒不成立。

### 只认出口级错误

- **出口级**：`abusive traffic`（403 信誉）、`FreeUsageLimitError`（429 配额）
- **非出口级**（记入 `other_err`）：上游 402「Endpoint is unavailable」、
  「maximum context length」

非出口级错误**不计错误、不累加连错、也不截断连错**（夹在两条 429 中间的 402
不能让两侧断开），且整窗只有 other 错误时不构成 `full_err`。

> 判据：换出口解不了这两类，切走纯属白切。

### 429 有两版文案，必须都认

免费层现版是 `Free usage limit reached. Subscribe to OpenCode Go...`
（type 仍 `FreeUsageLimitError`），旧版是 `Rate limit exceeded`。

只认旧文案时实测最近 2000 条错误里 **1751 条 429 全被判成非出口级**
→ `consec_err` 恒 0 → **87% 错误率下也永不换线**。

## 三、换到哪一条（选线四档）

`_warp_ip_rank()` 返回 `(档位, /64 是否刚用过, 排序值)`，调用方用 `min()` 取最优。

| 档 | 含义 | 为什么这个位置 |
|---|---|---|
| **0** | 从未出现在台账里 | 必然没被 opencode 见过，优先级最高 |
| **1** | 探针刚验过 OK | 探测器每条线都在跑，这是唯一**此刻**级别的正面证据 |
| **2** | 有过成功流量，且已过惩罚期 | 过了惩罚期不是废址；但没有新鲜探针结论，不如档 1 可靠 |
| **3** | 出现过但没有任何成功记录 | 切上去就报错那批，仅作兜底 |

**档 0 单列的理由**：「从没用过」与「用过但已久」在 `last_ip_ts` 上都可能返回
很小的值，混在一起排序会让刚清理掉的旧地址冒充新地址。

**档 2 的依据**：实测「上一次记录是已标记」之后再次出现的 6421 次里，
**96.5% 本次未被标记**，只有 3.5% 又被标记。过了惩罚期不等于废址。

**档内排序：越新越优先**（排序值取正，调用方用 `min()`）。刚刷出来的 OK 说明这个
地址这一刻还没被烧，压着它只是等它过期。

**档 1 与档 2 为什么是现在这个顺序（2026-11-05 对调）**：`last_ok_ts` 只由
**当前出口**挣得（`_record_active_ip_success`），且每次重启都清零
（`daemon.py:5163`）。于是它奖励的是「一直没被换下」，而不是「现在还能用」——
H2 这类被反复重启的线永远进不了档 1，而少数几条长期当出口的 CF/WG 长期垄断。
实测 13:00 那一小时 34 次换线、H2 零次，而池里平均有 8.1 条新鲜 H2 候选；
全天校准 A/E = 0.69（13:00 为 0）。对调后，探针 OK 是每条线都有、且是**此刻**
的结论，才配得上排在前面。完整证据见
[../analysis-20261105-h2-selection-bias.md](../analysis-20261105-h2-selection-bias.md)。

## 四、三个修正因子

### 4.1 /64 静置（同档内，跨档不比较）

`_warp_prefix_rest`：同档内优先选刚烧过的 /64 之外的地址。静置时间
`prefix_rest_sec = 300`。

**理由**：opencode 免费额度按出口段计，新 /128 落在刚用过的 /64 里，首条请求
照样 429。

**但段级信息不能升级成准入判据**：时间序回放（段状态取探前台账）显示，
T0 落在已烧段 OK=56/1024（5.47%），落在干净段反而只有 1/108（0.93%）。
**干净段里的全新地址并不更好。**

### 4.2 冷却中的线排最后

选到冷却中的线，`_refresh_idle_warp` 会直接返回 None，白白把这次换线推进落池。
兜底分支用 `max(probes, key=...)` 把冷却线压到末尾。

### 4.3 必须按出口 IP 去重，且不得等于当前出口

重连竞态会让两条隧道指向同一会话 IP，两条都进候选池 = 「换了隧道但 IP 没变」当换线。

`_exclude_active_ip()` 在**所有候选来源汇合之后**统一执行（缓存快速路径、
并发探测、同步刷新）—— 放在各分支里会被同步刷新分支绕过。

> 实测 2026-10-22 08:03~17:59 共 817 次换线里 **111 次（13.7%）新出口 == 旧出口**，
> 全部由 rate429 触发 —— 每一笔都白重启了一条隧道。

## 五、模型模式与历史模式

`_ip_history_is_truth()` 决定历史台账是否**否决**候选：

| 模式 | 历史的作用 | 生效条件 |
|---|---|---|
| **模型模式**（默认） | 只管**排序**，不准入 | 探测器正常 |
| **历史模式**（回退） | 重新获得否决权 | 探测通道失明 120s |

**为什么历史不能当否决项**：429 按出口段计、恢复期几小时，启发式经常与事实不一致。

**但惩罚期照旧排除**：`_warp_ip_is_blocked` 在两个模式下都是硬否决 —— 那是
「这个地址确实被拦过」的确定事实。

> 实测 7 个烧毁段里 648 个 /128 被逐个探测、**608 个（94%）判 quota**，
> 全是本该在探测前就挡住的。

## 六、冷却

| 场景 | 冷却 |
|---|---|
| 换线成功 | `cooldown_ok_sec = 5s` |
| 换线失败 | `cooldown_fail_sec = 3s` |
| 整窗全为出口级错误（`full_err`） | **绕过冷却** |

**为什么固定 5s、不做指数退避**：2^n 退避曾在风暴期锁死到 600s —— 实测
17:02~17:09 九分钟零换线、1752 条请求全废。

**5s 的依据**：新出口首条错误延迟 p25=0.7s / p50=1.6s / p75=4.5s。
1s 冷却会让 40% 的「刚换就错」在冷却后立刻再触发（日志里的锯齿来源），5s 覆盖 79%。

## 七、换线后必做

1. **重置主动轮换计时**（`_last_warp_switch_ok_ts`）—— 否则刚落池或刚原地重连，
   主动轮换仍按上一段的已服务时长算账，立刻再切一次。
2. **刷新被换下的闲置线**（`refresh_delay_sec = 20s`）。
3. **标记被换下的 IP**（`blocked=True`）并作废它的所有探测结论。
