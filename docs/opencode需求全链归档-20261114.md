# opencode 需求全链归档（2026-11-13 ~ 2026-11-14）

> 性质：**需求归档索引 + 全链总览**。整条需求 =「把 opencode 接入 ccs 会话体系（与 claude 同级、可选择）+ 走独立 asip 闸口防 429」，共七块落地，全部完成并验证。
> 深度论证与逐项裁决见各分册（文末《文档落位表》）；本篇是唯一入口，自包含可读。
> 证据环境：WSL Ubuntu（/home/administrator/），实测窗口 2026-11-13 ~ 11-14。

---

## 一、需求原话（用户口径）

1. 「把 asip 接入 ccs 的 opencode，拉一个独立的 asip 闸口，让 opencode 的流量都走这个闸口，opencode 正常用自家免费的 dsv4.1-flash 模型。ccs 拦截或监控到 opencode 的 429 请求，调 rotate 专门补充的换 opencode 闸口逻辑切换对应闸口 IP，最后 ccs 再把请求重试，所有 opencode 会话共享一个闸口。它的错误轮换不与其他闸口交互。」
2. 「记得 opencode 的逻辑，单独在 asip 开一个模块。」
3. 「如何查第八闸口的请求日志？没有 9router 中介的话，asip 要提供原生的日志查看。opencode.log，asip 能读就读，也放日志。」
4. 「我说了换 IP 能救，asip 就是干这个的，你按 asip 闸口的定义换给闸口换优质隧道，和其他闸口一样。」
5. 「ccs 命令的 help 提示不够。」
6. 「要允许 ccs 启动不记名角色只使用其 opencode 功能，不给予其他限制。可直接 ccs start 启动，然后以后的引擎默认 opencode。」
7. 「发现 bug，任务自然结束依然收到继续完成工作的提示。」

前置事实：opencode 免费额度按出口 IP 计（换 IP 即得新配额），只有 opencode.ai 免费接口能靠代理换 IP 绕过限额——这是整条链的成立前提（块 2/4 实测复证）。

## 二、七块总览（时间序）

### 块 1｜opencode 接入 session 三项目（引擎一等化）

- **诉求**：opencode 与 claude 同级——启动/投递/判活/自愈/上下文/状态六条链等价可用；引擎可选择且持久化，任何自动重启不得翻转引擎。
- **根因**：引擎不是一等概念——链路代码默认 claude，opencode 只能外挂。
- **做法**：三层声明（`persona.engine` → `--engine` → 哨兵事实源，优先级从低到高）+ 查表分派（`core._ENGINE_REGISTRY` / `tmux_ops._ENGINE_SPECS`）+ 评估面第三态 degraded（`passed=None`+reason，不静默假阴）。关键口径：P1 同级生命周期 / P2 可选且持久 / P3 不翻转 / P4 claude 零回归 / P5 评估诚实 / P6 术语不混（「引擎」两义：会话承载引擎 vs 工作流引擎 wf:engine）。
- **提交**：session-launcher 8（`7500306`…`803607c`）/ session-pipeline 3（`2231f83`/`15fcf40`/`0282708`）/ hermes-session-roles 1（`64eb7a4`），分支 `feat/opencode-engine`。
- **验证**：P1–P6 全数成立（P4 claude 启动命令字节等价；P3 三轮演练不翻转）；测试 518 / 1378+3 环境型失败 / 54 passed。三方六维度审查披露 4 缺陷（C-1/B1/B2/B3）+1 能力缺口（opencode MCP），全部修复复验。
- **分册**：审计稿 / 实现计划书 / 实现任务书 / 派工安排计划 / 子代理提示词集 / 六维度终审裁决（全套见 session-launcher/docs/）。

### 块 2｜opencode 独立 asip 闸口（slot-8）

- **诉求**：opencode 流量走专属闸口（所有 opencode 会话共享一个），原生直连 `api.opencode.ai` 的 `deepseek-v4.1-flash-free`（不经 9router）；429 时换闸口 IP；错误轮换不与其他闸口交互；opencode 逻辑单独开模块。
- **做法**：四层链路——
  1. **闸口层**：`asip/opencode_gate.py` 独立模块（334 行，全部业务逻辑；daemon.py 只接线 67 行，config.py 只加常量）。slot-8 / 端口 7898 / Clash API 9098 / selector `proxy`，独立选中态 + 账本 + 合并窗 800ms。
  2. **原生直连层**：launcher provider `oc-native` 段 + `HTTPS_PROXY` 闸口出口注入（端口三级发现：env → config → `GET /slots`，不硬编码）。
  3. **rotate 入口层**：`POST /rotate-opencode-gate`（同一 UDS/Token，独立 endpoint，不碰 `POST /rotate` 分发），回包七字段契约（`ok/switched/reason/switch_to_node/switched_at/active_egress/ms`）。
  4. **ccs 闭环层**：`ops/opencode_quota.py`——opencode.log 429 判据（两组化：原生 `AI_APICallError` + 包装 `AI_RetryError`）→ opencode.db 只读归属 → 调 rotate 换 IP → 唤醒会话重发，60s 冷却。
- **提交**：auto-switch-ip `c51ba2a` / session-launcher `5c48471`+`7ba361f`+`9185191`。
- **验证**：asip 1333 passed（+8）/ launcher 535 passed（+17，零新增失败）；四条红线实证全绿（claude 配方字节等价 / slot-1..7 零改动 / `POST /rotate` 分派体零改动 / 不中断在途）；部署后端到端真实调用 `switched=true` 换节点成功。
- **盲审修复**：B1 删 `proxy_port=7898` 静态值（防上线前打到死代理，改动态发现）；B2 补 `AI_RetryError` 包装形态判据（曾漏 12 会话）；B3 配置重复键合并。
- **分册**：论证体计划书 / 派工契约与提示词 / 六维度终审裁决（全套见 auto-switch-ip/docs/）。

- **提交**：auto-switch-ip `48494c7`。
- **分册**：无（本篇即记录）。

### 块 4｜429 闭环修活（持久宿主 + 杀重生唤醒 + P2C 选点）

- **诉求**（用户裁决）：「换 IP 能救」（实测成立：换新 IP 后请求成功生成 37.9K/54.6K 流式——免费限额是 IP 级）；按 asip 闸口定义给闸口换**优质隧道**，和其他闸口一样（P2C 选点）。
- **根因链（三个断点，全部实证）**：
  1. **监测器零宿主**：watchdog 线程随 `ccs.py start` 退出即死（daemon=True 线程不保活），`check_once` 从未执行，换 IP 账本只有冒烟记录；
  2. **opencode TUI 楔死**：撞 429 后进入内部退避「retrying in 17h 47m」（Retry-After 驱动），打字/esc 唤不醒，唯一解 = 杀 `.opencode/bin/opencode` 子进程（pane 重生循环自动拉起，上下文在 opencode.db 可续）；
  3. **选点非优质**：闸口均匀随机，与 slot-7 的 `pick_next_node`（P2C + 预检）不一致。
  另有判据陷阱：opencode.log 时间戳是 UTC；TUI 文案「Free usage exceeded」≠ 日志文案「Free usage limit reached」，两者都覆盖才算判据全。
- **做法**：
  - `run_once()` 持久宿主入口（`python3 -m ops.opencode_quota`）——offset/冷却表落盘 `~/.hermes/run/opencode_quota_state.json`（一次性宿主会重放日志重复轮换，必须持久化；首轮跳 EOF）；挂 `ccs-monitor-daemon`（systemd-run --user 瞬态单元 `ccs-monitor.service` 托管重启）60s 周期。
  - 唤醒改「杀子进程 + 续发」：换 IP **先于**杀；kill 判据 = 命令行含 `.opencode/bin/opencode`（绝不误杀 bash 重生循环/claude）；重生后发 C3 续发指令；ccs 缺证据路径零变化。
  - 选点注入 `pick_next_node`（P2C，`count_call=False`），与 slot-7 同源。
- **提交**：session-launcher `cd81642`（+308 行，测试 +6，全量 543 passed）；asip picker 注入随工作区累积入库 `a047fd6` 落地。
- **验证**：监控连续多轮「no hit this round」且 offset 持续推进（宿主真的在扫）；手动救援 2 次全链验证（换 IP→杀→重生→续发→正常）。

### 块 6｜不记名角色 + 引擎缺省 opencode

- **诉求**（用户放行令）：「允许 ccs 启动不记名角色只使用其 opencode 功能，不给予其他限制。可直接 ccs start 启动，然后以后的引擎默认 opencode。」
- **做法**：裸 `ccs start` → `ccs-anon` / 引擎缺省 **opencode**（三层优先级不变）；validators 白名单**移除**（用户裁决方案 A：不记名=未注册名全链放行，start/stop/send/wake 不设限），保留 `_ROLE_NAME_RE` 格式安全线（防遍历/注入）；start 未注册名显式打印「不记名角色（未注册，无 persona）」防 typo；19 个存量 persona 全部显式 `engine:"ccs"`，行为逐字不变（P4 零回归）。
- **提交**：session-launcher `7832f46`（549 passed = 543+7 新增−1 删除）。
- **验证**：真机冒烟——裸 start 起出 ccs-anon，`engine_source=sentinel`，opencode 进程带 `HTTPS_PROXY=http://127.0.0.1:7898`（闸口注入对不记名会话照常生效），`ccs stop anon` 干净回收。
- **有意行为变更（非零回归，已显著声明）**：`test_unknown_role_rejected` 语义改写为放行、`test_known_roles_refresh_after_persona_appears` 随 `_KNOWN_ROLES` 机制删除；全仓消费方排查该拒绝语义无其它消费方。
- **分册**：《交付-误判修复与不记名角色》。

### 块 7｜rate-recovery 引文误判修复

- **诉求**（用户报 bug）：「任务自然结束依然收到继续完成工作的提示」。
- **根因**（实证闭环）：会话任务自然收尾，产出报告里**引用**了历史失败文案（`429 FreeUsageLimitError`）；wt-live 的 workflow-engine（pipeflow daemon）rate-recovery 扫 pane 末 20 行时把引文误判成活限流，向已收尾会话两次发「上一轮 API 错误中断。继续…」。pane 判据实测只认出 0.67% 的错误轮（1342 条里 9 条），而 pane OR 分支恰好绕过「错误后有正常轮=已自愈不许打断」的既有语义。
- **做法**：触发只认转录错误轮（`_transcript_last_turn_is_api_error`），pane 文案只保留给配额/瞬时/终态分型；判定扩展 `_turn_text_starts_with_error`——整轮正文以 `API Error:`/`Please run /login` 开头才算（**只认开头不认包含**，引用错误文案的正常报告轮不算）。
- **提交**：wt-pipeline `8211a00` / session-pipeline `ab8ef33` / wt-live `508183b`（cherry-pick，**已生效**：journal 18:44:59 就地 re-exec 加载新代码，同 PID）。
- **验证**：独立复跑 35 passed；红绿反证（旧代码 2 red → 新代码全绿）；两分支全量零新增失败。13 个既有 pane-only 测试补转录写入属契约适配（断言零改动，diff 核过）。
- **分册**：《交付-误判修复与不记名角色》。
